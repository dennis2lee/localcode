# localcode

A coding agent that talks to three provider families: Amazon Bedrock, the Anthropic API directly, and any OpenAI-compatible endpoint (LM Studio, vLLM, and other local runtimes).

The model calls tools itself for file reads and writes, shell execution, MCP, and Skills. The core runs as a headless daemon. A TUI and a browser Web UI both attach to it as equal clients.

## Features

| Area | What you get |
|---|---|
| Providers | Bedrock, Anthropic API, OpenAI-compatible. Switch with one config file. Bedrock reads AWS configuration only when it is first used, so an unused entry cannot break local-only startup. |
| Auth | `localcode login bedrock` (AWS SSO device flow, no AWS CLI needed), `localcode login anthropic` (stores an API key) |
| One prompt, no window | `localcode run "what does this repo do?"` answers and exits. In process: no port bound, nothing written to the session list, and the prompt may come from stdin so one with newlines and quotes in it survives the trip. `--format text` streams for a person, `json` prints one object for a script, `stream-json` prints the event stream every other client reads. `--bare` loads nothing but the base prompt, which is what makes a comparison against another tool fair. `--session` keeps the conversation and routes it through a running daemon when there is one, since two processes writing one session directory is not something to arrange by accident. Smart Agent works here too: the same six specialists, the same orchestration prompt, and `Task`, `TaskBackground` and `TaskCollect`. A run does not exit while a sub-agent it launched is still working. |
| Permissions | opencode style allow/deny/ask rules, plus allow once, allow for session, or always allow at the prompt. `git` runs without asking by default; a bash line is checked per command, so an allowed prefix cannot carry `&& rm -rf ~` along with it, and each command is matched both as written and unquoted so a deny rule is not escaped by spelling it `"curl"`. Four switches, each belonging to the conversation rather than to the daemon: `/permission-skip-all` allows everything, `/permission-skip-tools` allows every tool prompt and still asks before a path leaves the project, and `/read-outside` and `/write-outside` answer those two halves. Current status shows under the prompt; click it for all four, the rules, and the directories this conversation has approved. |
| Scheduled tasks | Say when and it books instead of doing it now: `내일 아침에 테스트 돌려줘` books, it does not run. The model separates the time from the work and localcode reads the time, so the confirmation names the moment localcode read rather than the words the model passed. Also `/schedule 30분 뒤 run the tests`, or the ⏰ button under the prompt box, which asks for the moment and the request in two fields and echoes the time as you type it. The time is parsed by localcode, not by the model: relative, clock, named, weekday and absolute forms in Korean and English, with the particle belonging to the time rather than to the request, and a bare hour meaning the nearest one. A vague time (`나중에`, `later`) and a repeat (`매일`, `every day`) are each refused by name rather than guessed at. It runs in a session of its own under the conversation's workspace and permission switches, and the right panel gets a row with a light: blinking while it waits, solid once there is an answer nobody has read, grey once it has been read. Click it to read the result, with rename and delete buttons like a session row's. **It fires only while localcode is running** — a moment that passed while it was closed is reported as missed rather than run late, because the request was for a time. `/show-scheduled-task` is the same list in the TUI. |
| Hooks | Claude Code style shell hooks on `pre_tool_use`, `post_tool_use`, `user_prompt_submit`, `stop`, `session_start`, each running in the workspace of the session whose event triggered it |
| Multi agent | Per role model, prompt, and tool scope. Agents delegate through the `Task` tool. Tab or `/agent` switches agent without losing session context, in the TUI and the Web UI alike; `/model` in the TUI opens the same choice as a list, each agent shown with the model it resolves to, for when you do not already know the name. Matching prompts can auto delegate to a cheaper agent, keeping the main session's prompt cache intact; which prompts and which agent are both set from a panel under the prompt bar, applied to the next prompt and saved to config.json. |
| Debate | This conversation's agent writes; up to three other agents, each on its own model, read it and say what is wrong; it answers them; and that repeats. Three ways in: say so and the model separates who reviews, how many rounds and the work (localcode confirms its reading before spending anything), the ⚖️ button, or `/debate girl,tom 5 <what to do>`. The protocol is never in the prompt — a model told to repeat ten times inside one turn stops at three and reports it is done, and a task that still carries the protocol gives the author a second loop to run inside the first. The author keeps this conversation, its history and its cache; each reviewer keeps one sub-session of its own for every round, so in round four it still knows what it asked for in round one, and reviewers run at the same time and cannot see each other — a panel that reads the first opinion is one opinion with witnesses. A reviewer can read and run **this project's own check** (`verify_command` from config.json, no arguments, so the model chooses whether to run it and never what it runs) and can never write, `bash` included, since a shell command is not a path. It is shown what actually changed: `git diff HEAD` where there is a repository, labelled as the tool-call list where there is not. The approval is a boolean each reviewer sets rather than a sentence to interpret, all of them have to give it, and anything that is not an explicit approval is not one. It ends on approval, on the round budget (default 3, at most 10 — a round is one turn plus one per reviewer), or on a standoff of two rounds in which the author called no tool at all, and the closing line always says which. |
| Commands the model may run | Off by default, one switch: `/model-invocable on`, `model_invocable` in config.json, or the settings window. On, the model can run a built-in, a custom command or a skill itself, each as a turn of its own in the same conversation. Two levels, answering different questions: the switch is whether, and which is written down separately — a built-in is named in `model_commands` with its slash, a custom command or skill opts itself in with `model_invocable: true` in its own frontmatter — so turning the switch off does not throw away the choices. No wildcard, because the list includes `/permission-skip-all` if you write it. The name carries its slash and a call without one is refused rather than repaired, since a model that wrote `compact` may have meant the word. A command containing a `` !`shell command` `` cannot be model-invocable at all: that splice runs through neither the bash tool nor the permission gate, and the refusal is named rather than silent. The model decides when to run one from what it has read, so anything on the list is reachable from text the model did not write, and every surface says so. |
| Smart Agent | Off by default, one switch in the settings window. Turns the session's own model into an orchestrator and gives it six built-in specialists to hand work to: `explore` to find things, `librarian` to digest long material, `oracle` to review, `plan` to decompose, `implement` to make a self-contained change, `verify` to run the build. Each runs in its own session and its own context, so fifty files read to answer one question cost the main conversation a paragraph. Which model each one runs on is worked out from the profiles already in config.json rather than named in the build, and a profile called `smart-quick`, `smart-balanced` or `smart-deep` pins it by hand. `TaskBackground` and `TaskCollect` run several at once. No specialist can delegate, which is a tool allowlist rather than a line of prompt. |
| Search that admits what it did not look at | Three places `grep` did not look and did not say so. It stopped at 200 matches and returned 200 lines with no marker of any kind, which is not a truncated answer but a claim that the tree holds 200 matches. A file with a line longer than 64KB ended its own scan there, reported through an error nothing read, so a file holding the pattern twice came back clean. A file it could not open at all was skipped in silence. All three are fixed with no switch involved, because none of them is a better answer than the old one, it is a true one instead of a false one. Notices name paths rather than counting them, at most three of them, since a count repeats forever and cannot be acted on; and a search that withheld nothing still returns bare `file:line:text`. |
| Undo a turn | `/rewind` puts back the last turn: the exchange leaves the model's history, and every file `write_file` or `edit` changed in it is restored to what it was before that turn's first write. A file the turn created is removed. Run it again to go back another. The scope is Claude Code's, and the reply names its limits every time rather than once in a document: a shell command's writes are not covered, nor a background sub-agent's, nor your own edits, and a symlinked path or a file over 8 MiB is left alone and counted. It is session-level undo, not a substitute for version control. Pre-images live beside the session log and are deleted with it. It refuses where nobody is watching, and while a background sub-agent from the conversation is still working. |
| Start the model fresh | `/clear` leaves the model holding none of the conversation and the conversation holding all of it. Compaction replaces the history with a summary; this replaces it with nothing; neither removes anything. Every message stays on screen and in the log, and stays there after a restart, because the barrier is appended to the log rather than applied to memory. Cumulative token totals are deliberately unchanged: those tokens were spent. |
| Archive a conversation | A shelf, not a bin. A session that has gone quiet leaves the list keeping everything it had, the whole event log included, and comes back with one press. The `archive` button on a card or a drag onto the Archive header in the Web UI, `/archive` and `/retrieve` in the TUI. An archived conversation is still readable, which is the point of keeping it, and its log is still written to: a background task that outlives the archive still records that it finished. What it refuses is *starting* work, and one store-level invariant does most of that rather than a check at each caller, so a Task spawn, a synchronous delegation and a scheduled run are closed at once with no check-then-act. Refusals are 403 and never 409, because both clients read a 409 as "a turn is running" and queue behind it forever. Archiving is refused, not forced, while a turn or a background task or a scheduled run is going: deleting kills that work because the records are going away, and archiving has no such excuse. Retrieve restores the rank rather than the number, and says which. |
| Refer to another conversation | `#S2 has the final report. Check it against the file here.` A `#<name>` in a prompt resolves by id, exact title, or unambiguous title prefix, including into the archive. What it does **not** do is fetch anything: not one byte of the named conversation enters the message. A reference becomes a line of localcode's own text naming the conversation and saying its contents can be read with a tool, so the transcript arrives — if the model asks for it at all — as a tool result, which is the least trusted text there is and the right class for a mixture of somebody else's typing, a model's own words, fetched pages and MCP output. That is structural rather than a label: a tool result never re-enters the message path, so a `#S3` written inside the referenced conversation cannot resolve and a `/permission-skip-all on` inside it cannot reach the router that once ran exactly that. Non-transitive in both halves — a delegated prompt does not resolve references and a sub-agent is not given the tool — since one without the other is decorative. Nothing is ever refused: no match, several matches, or the conversation you are already in each produce a notice and the turn goes on, which a splice design could not afford. A conversation in another project is flagged as one, with both directories named. `#42` stays an issue number. The right arrow completes a name in both clients, splicing it into the sentence rather than replacing the box. |
| A tool name that is nearly right | A model that asks for `bash.command` used to be told only that no such tool exists, so it asked again, identically, until something else stopped the turn. A decorated name that unambiguously means one tool the agent actually has now runs it and says which spelling worked; anything else is refused with the roster of what it may call. Resolution searches only the tools that agent was offered, so a misspelling cannot reach past a `tools` restriction, and an ambiguous name is listed rather than picked. Underneath it, a real defect: the OpenAI streaming format lets a function name arrive in fragments, and localcode kept the first one — so a server that split `read_file` in two produced a call to `read_`. |
| Orchestration | Off by default, its own switch. `Task` lets a model delegate; it cannot make it commit to a shape. A model that says it will check each finding with three independent reviewers checks the first two and reports, and one told to repeat until nothing new appears stops at the third round. Neither is dishonesty: a stated procedure is a request. So the plan is data. The model authors it by filling in the `Orchestrate` tool's own input schema, which means the whole of it is checked before a token is spent (every agent against the roster the turn was admitted with, every reference against a stage that really precedes it, every count against a ceiling) and a plan that would not work is refused with the reason. Three stage kinds: one agent once, a fan out over a list or over an earlier stage's findings times N independent copies, and a barrier that sees everything kept. A stage that declares what it returns gets a tool in exactly that shape, and `keep` drops every result where one named field is false: that is the adversarial filter, with no expression language anywhere. A stage names a role rather than tools, intersected with the agent's own restriction, so a plan can neither hand `bash` to a reviewer nor widen what an agent may do. Every stage is a synchronous child, so Esc stops the whole run. 8 stages, 32 agent turns, 10 minutes a stage and 30 a run, all refusals rather than truncations, and the permission prompt shows those ceilings rather than an estimate it cannot keep. The report is written by localcode from what happened, not summarised by a model. Three ways to turn it on (the command, the settings window, config.json) and, with it on, the orchestrating turn's system prompt gains a policy saying when a plan is worth its cost: a switch that adds a tool and says nothing else has an invisible effect, since a run that never happens looks exactly like a switch nobody turned on. Written per model family, because the failure modes are opposite. |
| Concurrency where it is contended | `max_concurrent_tasks` bounded background sub-agents across the whole daemon, which is the wrong shape twice over: one local model on one GPU serves one request at a time whatever that number says, and a hosted provider on the same machine is then held to the same small number for no reason. A provider entry can now carry its own `max_concurrent_tasks`, bounding that one endpoint, and it is taken before the daemon-wide slot so a task queued on a busy local server is not holding a slot a hosted task could use. A test fails if the two are ever swapped. 0 or absent means no per-provider limit, so a configuration that does not use it is unchanged, and the daemon-wide default stays 1 rather than becoming a bill nobody agreed to. |
| Updating | A binary install localcode owns is replaced in place and localcode re-executes itself, so the same terminal and the same process id come back. A Windows `.msi` runs at basic UI, which is what makes it apply at all: at full UI, Windows Installer looks for a files-in-use dialog authored into the package before it offers to close what holds the files, this package has none because the tool that builds it cannot author dialogs, and the documented fallback is to show nothing and schedule a reboot. So the update used to report success and change nothing until the machine restarted. What it still does not do is restart localcode on Windows, and nothing can: the Restart Manager brings a console program back in a new console, not the terminal you are in, and a custom action or a helper process reach the same place. The reply says so rather than promising it. |
| The model knows where it is | The system prompt names the session's directory, re-derived every turn so it follows a workspace move instead of going stale. Nothing used to name it, so a model learned the directory from tool output and kept it in the conversation history: moving the workspace does not rewrite history, so it went on prefixing every shell command with `cd <the old path> &&` and files appeared in the project you had just left, while every question about the workspace was answered correctly with the new one. The boundary guard could not catch it and cannot: it checks paths, and a shell command is not a path. The line also says the part that matters after a move, that a path remembered from earlier in the conversation points at wherever the work was then. |
| Windows without a fight | Two ways `python` fails on Windows, both answered instead of left as a bare shell error. It resolves to a Microsoft Store stub that opens the Store: the model is told every spelling hits the same stub, and handed the `winget` line to run through the ordinary permission gate. Or it is not on PATH at all, which is what `python3: not found` usually means on a machine that has Python: conda, miniforge and miniconda ship no `python3.exe` at all, python.org's classic installers ship none either, and none add themselves to PATH. Keyed on PATH lookup rather than the shell's error text, which is translated on every non-English Windows. It names no interpreter as the project's, and does not search the disk: naming a conda base that cannot import the project turns one failed call into a wrong hypothesis to debug. The Store detector also stopped splitting commands inside quotes, which had been refusing `git commit -m "fix; python3 helper"` unrun. |
| Sharper tools | With Smart Agent on the file and search tools change further, because four of the six specialists have nothing else and the cheapest model in the roster is the one holding them. `read_file` pages: `offset` and `limit`, 800 lines by default, and a footer naming the lines you got out of the lines there are, so a long file is never read as a short one; a binary file is described instead of rendered as mojibake. `grep` skips binary files, and neither it nor `glob` walks version control internals or package caches; both name what they left out. No single file may take more than 30 of grep's 200 results, so one generated table cannot crowd the rest of the tree out of the answer. `glob` learned that the part of a `**` pattern after the stars may name directories: it was compared against the filename alone, so any pattern like `**/cmd/*.go` matched nothing whatever the tree held. A failed `edit` says why it failed: whitespace only, with the exact bytes at that line; CRLF; the line numbers where its first line does appear; or that nothing resembling it is in the file. A near miss is reported and never applied, because re indenting to make an edit fit changes the program in every language where whitespace is syntax. A successful `edit` hands back the lines it changed as they now stand, and `write_file` says how many lines the file it replaced had. The schema a turn was shown and the tool that then runs come from one pinned setting, so they cannot disagree. |
| Surviving a bad model | With Smart Agent on, a transient failure is retried on the endpoint that just failed before anything moves: up to two attempts, 1s then 2s, per endpoint, because the common rate limit is a blip and a fallback means a different model and a different cache prefix. A 401 or an unknown model id skips the wait, since time does not fix those, and a malformed request retries nowhere. When the retries are spent, a profile's `fallback` names where to go next: a rate limit, a 5xx, a refused connection, a credential that expired overnight. The switch re-derives the whole request rather than resending it with a different model id, because both the orchestration prompt and the per-model note are written per family, and it is recorded in the transcript so a session that quietly got worse cannot. A conversation too long for the window is not a fallback case: that is still summarized and retried where it was. |
| Knowing what it did | Smart Agent writes one JSON line per thing that happened to `~/.localcode/trace/`: which model answered and on which profile, what it cost including cache reads and writes, which tool ran and for how long, what was delegated to whom, every fallback and every compaction. One trace id per turn, inherited by every sub-agent, so a fan-out to three specialists greps back as one story instead of four unrelated logs. `GET /api/trace` tails it while a session is still open. Every model call also names the prompt assembly it was built from, so a fallback that reused the failed model's prompt is visible as an unchanged manifest id on a changed model family. The directory does not grow forever: a day's file is kept 30 days (`trace_max_age_days`), with an optional total size cap (`trace_max_total_mb`) that removes the oldest first and never touches the file being written. |
| What is in the prompt | The system prompt is assembled from a declared inventory rather than concatenated: each piece has a stable id, a source, a trust class saying whether it may be followed as instruction at all, a place in the request, and a condition saying when it applies. `/context` reports the assembly the next turn would send, with no model call: what is included and why, per category token estimates, the tool definitions (built-in and per MCP server) and conversation and reserved output against the window, and whether the request carries content that may not be followed as instruction. `/context all` also says what was left out and why. `/context <id>` reads back the manifest of a call that actually happened, from the record kept beside the turn log, bounded by the same two settings the log is. What a request names is derived from the messages it carries rather than from whatever the running call happened to create, so a tool result read three turns ago is still named as external content on every request that still sends it, including after a restart, and the preview reports the id the next request will actually carry. What a request names is every source whose authority is a question: a tool result, a file a command spliced in with `@path`, the output of a shell command it ran, a task written for a sub-agent, which carries one authority in the child's request and another in the parent's. Ordinary conversation is on the record as one digest, so two different conversations are two different requests without the report becoming a transcript index. Identities, hashes and sizes only, never the bodies. |
| Prompt cache | With Smart Agent on, the stable half of every request (the tool schemas and the system prompt) is marked as a cache breakpoint: `cache_control` on the Anthropic API, a `cachePoint` on Bedrock, nothing on a local server that already does its own prefix caching. A cache read is about a tenth of the price of reading it again, and each specialist's own session keeps its own prefix. The tail of the conversation is marked too, on the last of the last two messages: history is append-only, so each request reads the previous one's prefix at the cache rate and pays the premium only on what it added. Ignored harmlessly where the prefix is too short to qualify. |
| Guards | Files that look like a credential store (`.env`, `*.pem`, `id_rsa`, `~/.ssh`, `~/.aws/credentials`, `.netrc` and the rest) are refused outright for read, write and edit with Smart Agent on, and no skip unlocks them, because they are deny class and a skip downgrades ask. A path that leaves the session's own workspace is a question in its own right, always, judged on physical paths so a link inside the workspace aimed at `~/.aws` is outside, a file about to be created is judged by where its link leads, and a path that cannot be resolved at all costs one question rather than one blind allow. It covers `read_file`, `grep` and `glob` as reading and `write_file` and `edit` as writing, with a switch for each half; bash is not covered and does not claim to be, since a shell command is not a path. The question is answered by place: this directory for the rest of the session, or anywhere outside the project, and `/read-outside mem-clear` forgets the directories. `permission-skip-tools` does not silence it; only `permission-skip-all` does. Every turn's system prompt also states which sources are instructions (you, the prompt, the project's rules) and which are data (every tool result), and MCP output arrives wrapped in a marker naming its server. That is labelling, not enforcement: the permission gate stays the control. One place where a label was not enough has been closed: a sub-agent's task used to be walked through the slash-command table before any model call, so a task beginning `/permission-skip-all on` flipped the child's permission switch, did no work, and returned the command's confirmation as its answer. A delegated task is now work, not a command; a person typing in that same child session still gets commands. |
| Lifecycle hooks | Beyond the tool hooks: `pre_model` (block a request before it is sent, or print `{"context":"..."}` to inject a fact the model could not look up), `post_model`, `delegate` (refuse a sub-agent outright, which a prompt cannot do), `compact`, `retry`. |
| Config | One file: `config.example.json` is the reference, every key with a note on it, and a worked orchestration setup — the three `smart-*` profiles, the switch on, and the six specialists' prompts written out, with a test holding that block to the roster localcode actually builds. Copy it and the orchestration is already set up; what it still needs is a credential, because every provider it declares is checked at startup whether a profile uses it or not, so the `anthropic` block wants a key or deleting. It parses with nothing exported: the `{env:...}` illustrations live in the notes, and a required one there used to stop the file loading at all. Your own config may be JSONC: `//` and `/* */` comments and a trailing comma, and comments survive the writes localcode makes to it, because a rewrite that ate them would eat the point of having them. |
| Config from the environment | Any string in config.json may be `{env:NAME}`, or `{env:NAME:-fallback}` when it is optional, and is read from the environment as the file loads — API keys, a base_url, a model id, an MCP server's own environment, anything that differs per machine. The same spelling opencode uses. A variable that is missing is an error naming it and the field that asked for it, not an empty string that fails later as a 401. What is on disk stays a placeholder: every write rewrites one key of the file itself, so saving a setting never turns it into the secret it stands for. |
| Project context | `AGENTS.md` with `@path` imports and a `CLAUDE.md` fallback, read from the workspace of the session that is asking — so two sessions in two projects each get their own, and editing the file takes effect on the next message. `~/.localcode/AGENTS.md` and `~/.claude/CLAUDE.md` both apply everywhere, so an existing Claude Code setup is reused rather than replaced. `/init` to draft one, custom slash commands in `.localcode/commands/*.md`, auto memory the model writes for itself across sessions |
| A local model's thinking | A model that reasons before it answers streams that reasoning in a field the OpenAI API does not have, so every runtime invented one: `reasoning_content` on DeepSeek, vLLM, SGLang, LM Studio, llama.cpp and Ollama, `reasoning` on OpenRouter and others. Both are read. The TUI says **thinking** in its status line while it arrives and the Web UI shows the text above the answer, which is the difference between watching a model work and watching it run tools in silence. It is watched and then forgotten: never written to the session log, so a reload does not bring it back, and never sent back to the model. |
| Effort | How hard the model is asked to think, as one word: `off`, `low`, `medium`, `high`. Set it on a profile (`"effort": "high"`), or with `/effort` for one conversation, which wins — the same model answering "which file is this in" and "why does this deadlock" wants different amounts, and without a per-conversation answer the only way to have both would be two profiles on one model. **Unset by default and unset sends nothing**, so a request from anybody who has not asked for a level is byte-identical to what it was. One word, several wires, and the difference is reported rather than smoothed over: an OpenAI-compatible server is sent `reasoning_effort`, so a muse or a gemma that supports reasoning takes the level and one that does not ignores the field; the Anthropic API is sent extended thinking, where the newest Claude families size their own reasoning — every level reaches the same switch there, which `/effort` says in as many words — and older ones take a token budget per level. Bedrock carries the same thing through `additionalModelRequestFields`, merged with the million-token beta rather than overwriting it, and returns its reasoning as content blocks that go back on the one message a continuation needs them on. Two consequences are handled rather than left to fail: a budget is fitted to the profile's `max_tokens`, because it is spent out of that and the shipped example pairs 8192 with a level worth 16384; and temperature is dropped from a request that asks for reasoning, because the API refuses both together. Reasoning is shown while it happens, in its own muted block in the Web UI and as the busy indicator's word in the TUI, and is never written to the log: the API does not want it back, and a transcript that keeps it doubles the scrolling for something nobody reads twice. |
| Model quirks | A model whose id says it needs it gets one extra line of system prompt, and nothing else is told anything. A muse model that stops mid-task is told to carry on, up to a few times per turn, and no other family ever is; `/keep-going` or the settings window checkbox turns it off, one switch with two homes kept in step. Gemma writes `$\rightarrow$` and `$\text{name}$`, which needs MathJax to read as anything; it is asked for the character instead, and the Web UI unwraps the ones that arrive anyway. A model that ends its turn describing the next step instead of taking it is asked to take it, and is told to carry on up to three times per turn when it does it anyway — not when nothing ran, when a tool was refused, when it asked you a question, or when you have already typed the answer. `keep_going` on the profile sets the number, or `-1` turns it off. |
| Conversation | `/compact [instructions]` on demand, automatic compaction past a threshold (`/auto-compact 70` moves it, 50% by default), `/usage` for cumulative tokens per model (token counts only, no dollar figures). The three settings that change how a turn behaves each have a command of their own, answered by the daemon so both clients have them: `/smart-agent`, `/auto-delegate`, `/permission-skip-all` and `/keep-going` toggle with no argument, take `on` or `off`, and save the choice to config.json the way the settings window always has; `/reset-mcp` and `/reset-skills` apply an edited configuration without a restart. |
| Context limits | The window is read from the server (`GET /v1/models`, or `/props` on llama.cpp) rather than guessed from the model's name, which for a local server cannot be right: it serves whatever was loaded, usually with a smaller window than the model supports. A request refused for being too long does not end the turn: the conversation is summarized, and if that is not enough it is trimmed, shrinking each time until the server accepts it. Sized against the conversation's measured length rather than a window figure, because the character estimate runs about 4x low on Korean and Japanese. Tool output is capped at a quarter of the window as it arrives, so one large file cannot fill the context by itself. A reply cut off by `max_tokens` says so instead of just stopping. |
| Restart safety | Session list, conversation context, and `/usage` totals all restore from disk after a daemon restart. `/session` switches conversation from inside the TUI, which previously meant restarting it: the event stream is exchanged, and anything belonging to the conversation being left goes with it. A second terminal in the same project attaches to the daemon the first one started rather than failing on the port; one in another project starts its own, since a daemon stamps its directory onto the sessions created on it. |
| Workspace | Per session, not per process. Every relative path and bash command resolves against the directory of the session it belongs to, so two sessions can work in two projects at once on one daemon, and reopening a conversation puts you back in its project. Only that session's own turn blocks its own switch. |

## Architecture

```
[core daemon]  sessions, agent loop, tools, MCP, Skills, providers, task manager
   |- HTTP API   create session, send message, answer permission, spawn background task
   |_ SSE        token stream, tool start and end, permission requests, task status
        ^              ^
     [TUI]         [Web UI]   both are first class clients on the same API
```

A session is an append only event log, not an array of messages. Close the TUI or open a new browser tab and it resumes from a single `since` sequence number.

## Install

**Ubuntu, Debian, any Linux, and macOS from the command line. No root:**

```bash
curl -fsSL https://raw.githubusercontent.com/dennis2lee/localcode/main/scripts/install.sh | sh
```

One static binary in `~/.local/bin/localcode`. Nothing is written outside `$HOME`, no package manager is involved, and you are never asked for a password, which is what you need on a machine you do not administer. The download is checked against the SHA-256 GitHub publishes for it. Options go after `-s --`: `--version x.y.z`, `--dir ~/bin`, `--uninstall`. Running it again is the upgrade.

`~/.local/bin` is the directory Ubuntu's own `~/.profile` puts on PATH when it exists; the script prints the line to add if this shell does not have it yet.

**Other ways:**

| Where | How |
|---|---|
| Ubuntu or Debian, for every user on the machine (needs root) | `sudo apt install ./localcode-x.y.z-linux-amd64.deb` from the [releases page](https://github.com/dennis2lee/localcode/releases) (`-arm64.deb` on ARM) |
| Windows | `localcode-x.y.z-windows-amd64.msi`, or the portable `.zip` on ARM64 |
| macOS, as an app | `LocalCode-x.y.z-darwin-universal-app.tar.gz`, unpacked into `/Applications` |
| From source | `go build -o localcode ./cmd/localcode` |

See [INSTALL.md](docs/INSTALL.md) for all of them, including what to do when `apt` refuses a local file.

## Quick start

```bash
mkdir -p ~/.localcode
cp config.example.json ~/.localcode/config.json
```

Edit `~/.localcode/config.json` and set your Bedrock region and model IDs, or the address of your local LLM. An API key can stay out of the file entirely: any value may be `{env:NAME}`, read from the environment as the file loads. Then run:

```bash
localcode --agent general-purpose
```

The default run starts a local daemon and attaches the TUI to it. Open the same address (`http://127.0.0.1:4096`) in a browser to use the Web UI at the same time.

To run the daemon on a remote machine with `--headless` and attach from your laptop with `--server`, see [USAGE.md](docs/USAGE.md#remote-daemon-over-an-ssh-tunnel).

## Tests

```bash
go test ./...
```

That includes the Web UI: `internal/daemon` shells out to the JavaScript suite
in [test/webui/](test/webui/), which loads the shipped `index.html` and the
real `static/js/*.js` ES modules into a hand-written DOM (Node's built-in test
runner, no dependencies). It skips itself when `node` isn't installed. To run
only that part while editing the page:

```bash
make test-js
```
